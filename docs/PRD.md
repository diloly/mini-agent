# mini-agent 产品需求文档（PRD）

> 版本：v1.0 · 编写：许清楚（产品经理） · 下游：高见远（架构师）
> 本文档为 MVP 阶段的**精简 PRD**，不含竞品分析与市场调研。

---

## 1. 项目信息

| 项 | 内容 |
|---|---|
| 项目名 | `mini-agent` |
| 落地路径 | `E:\code\LocalAgent\mini-agent`（在已有项目根目录下新建子项目） |
| 形态 | Electron 桌面应用（Windows 优先） |
| 技术栈 | Electron + Vite + React + TypeScript + Tailwind CSS |
| UI 库 | **不使用 MUI**（Material 风格偏花哨，与用户「简约、不要花里胡哨」的明确要求冲突）。全部样式由 Tailwind + 少量自研组件实现 |
| 目标读者 | 架构师（用于系统设计）、开发、验收人 |

### 原始需求复述

> "帮我做一个 workbuddy 这样的 electron 打包的桌面智能体。不用全量做，先给出架构。再做最简单的版本，即对话记录，输入输出。模型支持接入 deepseek（需用户自己配 apikey）支持本地 ollama 模型（方便我随便测试）。风格样式跟 workbuddy 差不多的简约就行，我不喜欢太花里胡哨的"

### 验收约定（重要）

本项目**禁止任何形式的 lint / 单测 / 编译校验 / 冒烟测试命令执行**，也禁止启动浏览器做截图或 DOM 校验。
所有验收标准的判据只有两类：
1. **静态核对** —— 人工阅读源码 / 配置文件，确认实现存在且符合要求；
2. **手动运行核对** —— 由**用户本人**启动应用后肉眼确认表现。

PRD 中不存在「通过测试」「CI 通过」之类的验收表述。

## 2. 产品目标

**一句话**：一个本地运行、极简外观的桌面 AI 对话客户端，能记住历史会话，并可自由切换 DeepSeek（云端）与 Ollama（本地）两类模型。

| # | 目标陈述（Goal） | 衡量方式 |
|---|---|---|
| G1 | **可用**：完成从「输入问题 → 得到回答」的完整闭环，并支持多轮上下文 | 用户手动发起 ≥3 轮对话，模型回复能正确引用上一轮内容 |
| G2 | **可换**：用户可自行配置并随时切换 DeepSeek / Ollama，无需改代码 | 用户手动在设置页填入 API Key 或 Ollama 地址后，主界面下拉框即可切换模型并成功对话 |
| G3 | **可留存**：对话数据本地持久化，关闭重启后不丢失，可随时回溯 | 用户手动关闭并重启应用，会话列表与消息内容完整恢复 |

> 三条目标相互正交：**能用 / 能换模型 / 能留住数据**。任何一条不成立即视为 MVP 失败。

## 3. MVP 范围界定

### 3.1 本期做（In Scope）

| 类别 | 内容 |
|---|---|
| 会话 | 会话列表、新建会话、切换会话、重命名、删除 |
| 对话 | 多轮上下文对话、消息收发、中/英混排文本渲染 |
| 渲染 | Markdown 基础渲染（标题、列表、代码块 + 语法高亮、行内代码、链接） |
| 模型 | DeepSeek（OpenAI 兼容协议）接入；Ollama 本地模型接入；运行时模型切换 |
| 配置 | API Key 填写与本地保存、Ollama Base URL 配置 |
| 存储 | 会话与消息本地文件持久化；应用重启后恢复 |
| 打包 | 产出 Windows 可执行产物（脚本就绪，由用户手动执行） |

### 3.2 本期不做（Out of Scope，明确排除）

| # | 排除项 | 说明 |
|---|---|---|
| 1 | 工具调用 / Function Calling | 本期仅「输入输出」，无外部工具执行能力 |
| 2 | Agent 技能系统 / 插件市场 | 无技能包、无插件装载机制 |
| 3 | 多模态（图片/语音/文件输入） | 仅纯文本 |
| 4 | 云同步、用户账号体系、登录鉴权 | 纯本地单机应用 |
| 5 | 多窗口 / 多标签 | 单窗口单会话视图 |
| 6 | 代码 Diff 渲染、富文本编辑器、表格交互式控件 | Markdown 之外的复杂富交互一律不做 |
| 7 | 消息编辑 / 重新生成、分支对话树 | 线性单一对话流 |
| 8 | 流式以外的富交互 | 详见下方说明 |
| 9 | 深浅色主题切换、自定义主题 | 仅提供浅色单一主题（见 UI 章节） |

> **关于流式输出**：MVP 允许「一次性返回整段答案」即可满足 G1。流式打字机效果是 **P1 增强项**，若架构上顺手则实现，不作为 MVP 阻塞项。

## 4. 用户故事

| ID | 用户故事（作为……我希望……以便……） |
|---|---|
| US-1 | 作为一个**日常提问的用户**，我希望在一个输入框里连续追问同一个话题，以便模型能记住前几轮我说过的话、不用我反复复述背景。 |
| US-2 | 作为一个**想省钱/想离线的用户**，我希望在界面上直接切换 DeepSeek（云端）和本机 Ollama（本地）模型，以便我在没网或不想烧钱时也能随便测试。 |
| US-3 | 作为一个**第一次使用的用户**，我希望在设置页填写自己的 DeepSeek API Key 并自动保存到本机，以便下次打开不用重新粘贴，同时不用担心 Key 被上传到别处。 |
| US-4 | 作为一个**长期使用者的用户**，我希望所有历史会话都保存在本地并在左侧栏列出，以便我随时点开回看上周问过的内容和当时的回答。 |
| US-5 | 作为一个**话题多杂的用户**，我希望一键新建干净的会话，以便不同话题互不干扰、上下文不会串味。 |

## 5. 需求池

优先级定义：**P0 = 必须有（MVP 阻塞）｜P1 = 应该有（体验完整度）｜P2 = 锦上添花**

### 5.1 P0 —— 必须有

| ID | 需求描述 | 验收标准（静态核对 / 手动运行） |
|---|---|---|
| **CH-01** | 多轮对话：输入框支持回车发送、Shift+Enter 换行；发送后把「本会话全部历史消息」作为上下文传给模型 | 静态：源码中存在按会话维度累积 `messages` 数组并在请求体中传出的实现。手动：连续问 3 轮，第 3 轮回答能正确引用第 1 轮信息 |
| **CH-02** | 消息列表渲染：用户消息右对齐气泡、助手消息左对齐非气泡；自动滚动到底部 | 静态：存在消息列表组件且依据 `role` 分支渲染。手动：发送后视口自动跟随最新消息 |
| **CH-03** | Markdown 基础渲染：标题、无序/有序列表、代码块 + 语法高亮、行内代码、链接 | 静态：存在 Markdown 渲染器与代码高亮依赖。手动：让模型输出一段含代码块的回答，代码块带底色且有着色 |
| **UI-01** | 三区布局：左侧会话栏（260px）+ 右侧主聊天区（消息区 + 底部输入区） | 静态：布局组件树包含侧边栏/消息区/输入区三个区域，样式表有对应宽度约束。手动：窗口拉伸时消息区自适应、输入区不被遮挡 |
| **SM-01** | 新建会话：左侧栏顶部「新建会话」按钮，点击生成空会话并聚焦输入框 | 静态：存在创建会话的处理函数与数据写入逻辑。手动：点击后聊天区清空、列表顶部出现新条目 |
| **SM-02** | 会话列表与切换：按最近更新时间倒序列出会话，点击切换内容互不串台 | 静态：列表按 `updatedAt` 排序。手动：建 2 个会话各发 1 条消息，来回切换内容正确隔离 |
| **ST-01** | 本地持久化：会话与消息以文件形式写入用户数据目录，应用重启后完整恢复 | 静态：存在存储读写模块与落盘路径（在 Electron `userData` 目录下）。手动：关闭再打开，会话列表与消息原文一致 |
| **PR-01** | Provider 抽象层：统一的 `LLMProvider` 接口（`chat(messages, model)`），上层 UI 不感知具体厂商 | 静态：存在接口定义文件及 ≥2 个实现类（OpenAI 兼容 / Ollama），UI 层无厂商专属字段名 |
| **PR-02** | DeepSeek 接入：基于 OpenAI 兼容协议调用聊天接口 | 静态：存在 API 地址、请求体、鉴权头构造代码。手动：填入合法 Key 后可正常获得回复 |
| **PR-03** | Ollama 本地接入：调用本地服务的聊天接口，Base URL 可配置（默认 `http://127.0.0.1:11434`） | 静态：存在 Ollama 请求构造代码且 Base URL 可配置。手动：本地起服务后可选择模型并对话 |
| **CF-01** | API Key 配置与保存：设置面板支持填写 DeepSeek API Key，保存到本地配置 | 静态：存在配置读写模块，Key 未硬编码在源码中。手动：填 Key → 重启应用 → Key 仍在 |
| **CF-02** | 模型切换：主界面提供模型下拉选择器，切换后立即对新消息生效 | 静态：下拉数据源来自已配置 Provider 列表。手动：切换 DeepSeek ↔ Ollama 后各发一条消息，均成功 |
| **ER-01** | 错误态处理：网络失败、鉴权失败、模型未启动等错误在消息区给出可读中文提示 | 静态：请求调用处存在异常捕获分支。手动：断网或填错 Key 后发送，界面给出明确错误文案且不白屏崩溃 |
| **ER-02** | 加载态处理：等待回复时输入框禁用并显示「生成中」，期间消息区不卡死 | 静态：存在请求进行中的状态位。手动：询问一个耗时较长的问题，期间界面可正常滚动查看历史消息 |
| **ER-03** | 模型未配置态：未填 Key / 未连 Ollama 时，给出引导到设置页的提示，而非静默失败 | 静态：存在「未配置」的判断分支与引导文案。手动：清空配置后发送，出现「请先配置模型」引导 |
| **PA-01** | Electron 工程与安全基线：主进程 / 预加载脚本 / 渲染进程三层结构，开启 `contextIsolation`，关闭渲染进程直接 Node 访问 | 静态：配置文件中 `contextIsolation: true`、`nodeIntegration: false`，渲染层仅通过受限 IPC 通道调用主进程 |
| **PA-02** | 打包脚本就绪：提供桌面端打包脚本与产物输出配置 | 静态：包管理脚本中存在打包命令。手动：由用户自行执行打包命令产出 Windows 安装包 |

### 6.1 整体布局

```
│  侧边栏      ├──────────────────────────────────────────────────────┤
│  260px       │                                                      │
│  背景 #FAFAFA│  消息区 flex-1：                                     │

│ ───────────  │    · 两侧最大宽度 720px，居中排版                     │
│ ○ 会话标题 A │    · 行间距宽松，字号 14px                            │
│ ○ 会话标题 B │                                                      │
│ ○ 会话标题 C │                                                      │
│   (最近更新  ├──────────────────────────────────────────────────────┤
│    倒序)     │  输入区（最大高度 160px）：                           │
│              │    · 圆角 8px 文本框，边框 #E4E4E7                    │
│              │    · 右侧发送按钮（主色实底）                         │
│              │    · 底部一行灰色小字：Enter 发送 / Shift+Enter 换行   │
└──────────────┴──────────────────────────────────────────────────────┘
```

### 6.2 色板方向

| 角色 | 取值 | 说明 |
|---|---|---|
| 主背景 | `#FFFFFF` | 纯白，不使用渐变 |
| 侧边栏背景 | `#FAFAFA` | 与白对比极弱，靠 1px 边框分隔而非阴影 |
| 分割线 / 边框 | `#E4E4E7` | 唯一描边色 |
| 主文字 | `#18181B` | 高对比，保证可读性 |
| 次要文字 | `#71717A` | 时间戳、提示语 |
| **单一强调色** | `#2563EB` | 仅用于：发送按钮、输入框聚焦边框、选中态指示、主链接 |
| 危险色 | `#DC2626` | 错误文案、删除操作 |
| 用户消息块 | `#F4F4F5` | 极浅灰，避免彩色气泡 |

**硬规则（简约红线）**：
- 全局**零渐变**；阴影最多允许 1 层 `0 1px 2px rgba(0,0,0,0.04)`，且仅限下拉/弹层；
- 圆角统一：`6px`（按钮、输入块）/ `8px`（卡片、输入框）；
- **无插画、无图标背景块、品牌 Logo 仅 1 处**（侧边栏左上角文字标）；
- 强调色在一屏内出现不超过 2 处（按钮 + 选中态）；
- 字体：`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`；正文 14px / 标题 15px / 提示 12px。

### 6.3 关键交互状态

| 状态 | 表现 | 触发条件 |
|---|---|---|
| **空态** | 消息区居中显示两行文字：`有什么可以帮你？` + 副标题 `在下方输入内容开始对话`。下方为一个灰框示例提示条（可点击填入输入框）。无图片、无 SVG 插画 | 会话内 `messages.length === 0` |
| **加载中** | 助手消息位显示 `生成中…`（文字跳动动画，颜色 `#71717A`）；输入框禁用（`#FAFAFA` 底 + 不可输入）；发送按钮变为方形「停止」图标 | 请求进行中 |
| **错误态** | 在最后一条助手消息位置渲染浅红底（`#FEF2F2`）块：标题 `请求失败` + 中文原因 + 一行「重试」文字按钮。不弹系统弹窗、不清空上下文 | 网络失败 / 401 鉴权失败 / 服务不可达 |
| **模型未配置态** | 顶部下拉框显示灰色 `未配置模型`；输入区上方出现一条浅黄提示条（`请先配置模型` + 「前往设置」文字链接），发送按钮置灰不可点 | 无任何已配置 Provider 或当前 Provider 缺 Key/地址 |
| **Ollama 未启动态** | 错误文案明确区分于网络错误：`无法连接本地 Ollama 服务，请确认已启动 ollama serve`。下拉框中本地模型项标灰 | Ollama 请求 `ECONNREFUSED` |

## 7. 待确认问题

> 每项均已给出**推荐默认值**，用户不回复即按推荐值执行，不阻塞架构设计。

| # | 待确认问题 | 推荐默认值 | 影响面 |
|---|---|---|---|
| Q1 | 是否需要**流式输出**（打字机效果）？ | **推荐：放到 P1，架构预留接口**。MVP 先整段返回，但 Provider 接口设计为可产生增量回调，后续无痛补上 | Provider 接口签名、消息区渲染逻辑 |
| Q2 | 本地数据用**单文件 JSON** 还是**嵌入式数据库**？ | **推荐：单文件 JSON（按会话切分存储）**。MVP 数据量小，便于用户手动查看备份，零额外依赖 | 存储层实现、后续迁移成本 |
| Q3 | API Key 落盘方式？ | **推荐：系统凭据优先（Windows Credential Vault），失败回退本地加密文件**。不引入重型依赖 | 安全基线、CF-04 验收口径 |

## 8. 附录：给架构师的要点提示

1. **Provider 抽象是全局最重要的一根横轴**：所有 UI 交互不得出现 `deepseek` / `ollama` 字样，统一走 `LLMProvider` 接口，为后续接入更多模型留位。
2. **安全底线**：渲染进程不得直连云（Key 泄露风险 + CSP 限制），所有带 Key 的请求必须走主进程发起。
3. **存储层隔离**：会话数据与配置数据分文件存储，便于用户清理历史而不丢失 Key。
4. **界面复杂度预算**：任何新增 UI 元素若不能归因到 US-1~US-5 中的某条用户故事，默认不做。
