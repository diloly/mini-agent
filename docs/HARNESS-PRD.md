# mini-agent · Python Agent Harness 本期范围定义

> 版本：v1.0 · 编写：许清楚（产品经理） · 下游：高见远（架构师）
> 本文档只回答一件事：**这层 harness 本期做什么、不做什么、怎么算做完**。不含技术选型细节与竞品分析。

---

## 0. 背景与定位

| 项 | 内容 |
|---|---|
| 现状 | `E:\code\LocalAgent\mini-agent` 已是一个可运行的 Electron + React + TS 桌面聊天客户端，直连 DeepSeek / Ollama，流式打字机正常 |
| 变化 | 增加一层 **Python agent harness**（用户点名 LangChain），负责调模型循环、工具调用、规划、记忆 |
| 变化后形态 | Electron 退化为**纯 UI 前端**；Python 进程成为**唯一的智能与副作用来源** |
| 本期性质 | **能力升级**，不是重写。UI 侧的会话历史、流式、模型切换、配置继续保持可用 |

**一句话定位**：把「一问一答」升级为「agent 自己动手把事情办完，并把过程摊开给用户看」。

> 🚫 **项目级硬性禁令（本文档同样适用）**：任何阶段不得执行 lint / 单测 / 编译校验 / 冒烟测试命令，不得跑 build / dev / pip / npm，不得启动浏览器截图或做 DOM 检查。本文所有验收判据均为**静态可核对**或**用户手动运行肉眼确认**。

## 1. 它要帮用户干什么（用户故事）

| ID | 用户故事（作为……我希望……以便……） | 价值锚点 |
|---|---|---|
| US-1 | 作为一个**懒得自己查资料的用户**，我希望只说一句「帮我查一下 XXX 最新情况并总结」，agent 就自己发起搜索、看几条结果、汇总成带来源的回答，以便我不用手动复制粘贴。 | 信息获取自动化 |
| US-2 | 作为一个**手上有本地文件（日志 / 代码 / 笔记）的用户**，我希望把文件路径给 agent，它自己读取后基于内容回答（如「这段日志报错原因是什么」），以便我不用把文件内容整段贴进对话框。 | 本地上下文接入 |
| US-3 | 作为一个**需要准确数字的用户**，我希望需要算术时 agent 自己调计算工具而不是心算，以便结果可信、不算错。 | 确定性计算 |
| US-4 | 作为一个**想搞清楚 agent 到底干了啥的用户**，我希望界面上能看到它每一步的「调用了什么工具、传了什么参数、拿回什么」，并且能随时打断，以便我不盲信它的结论、也不怕它跑偏烧钱。 | 过程可见 + 可控 |
| US-5 | 作为一个**遇到工具失败的用户**，我希望 agent 能自己换个法子重试（换关键词、换文件），实在不行就明确告诉我哪一步失败、为什么，以便它不会静默卡死或假装成功。 | 失败可解释 |

> US-4 与 US-5 是本期的**质量门槛**：一个只会偷偷调工具、失败就静默的 agent，即使功能跑通也不算做完。

## 2. MVP 工具集（本期只给 3 个）

| # | 工具 | 用途 | 对应故事 |
|---|---|---|---|
| T1 | `web_search` | 关键词网页搜索，返回标题 + 摘要 + 链接 | US-1、US-5 |
| T2 | `read_text_file` | **只读**读取用户指定的本地文本文件（txt / md / log / json / 代码），带大小与行数上限 | US-2 |
| T3 | `calculator` | 四则运算 / 百分比 / 幂与开方等确定性计算 | US-3 |

### 为什么是这三个

1. **覆盖三类最小能力**：对外取信息（T1）、读用户已有上下文（T2）、做无歧义运算（T3）。三者互不重叠，合起来足以拼出「多步任务」。
2. **全部只读、零副作用**：不写文件、不发消息、不执行命令，**最坏情况只是拿到错误信息**，不可能造成不可逆损坏。这是本期安全红线的直接体现。
3. **每个都能被用户肉眼验证**：搜索结果对不对、文件读得对不对、算得对不对，看一眼就知道，不需要任何自动化手段。
4. **不依赖用户的额外账号**（除 T1 可能需要的搜索 Key，见待拍板项 P2）。

### 明确不做的工具

写文件、删/移动文件、执行 shell 或 PowerShell、运行代码、HTTP 任意请求、发邮件 / 发消息、浏览器自动化、数据库读写、安装依赖。

## 3. 安全红线（绝对禁止 agent 执行）

> 实现层面的要求：**白名单机制** —— 未注册的工具一律拒绝；工具参数中的路径必须做规范化并限制在允许范围内（阻断 `..` 穿越）；未命中白名单即报错，不静默。

### 3.1 禁止的操作（任何情况下）

| 类别 | 具体禁止项 |
|---|---|
| **文件破坏** | 删除、移动、重命名、覆盖、清空任何文件或目录；创建新文件 |
| **文件越权** | 读取允许范围之外的路径；读取凭据类文件（`.env`、私钥、`~/.ssh`、浏览器密码库 / Cookie、系统凭据管理器） |
| **系统改动** | 修改注册表、系统设置、环境变量、计划任务、系统服务、防火墙、代理配置 |
| **命令执行** | 执行任何 shell / cmd / PowerShell / 批处理 / 脚本；启动任何外部进程 |
| **软件生命周期** | 安装、卸载、升级、降级任何软件或依赖包 |
| **对外通信** | 发邮件、发 IM 消息、发 Webhook、发帖、提交任何表单、下单、支付、上传用户文件到任何外部服务 |
| **网络越界** | 访问局域网其他设备 / 内网服务 / 本地管理端口（搜索与模型 API 除外） |

### 3.2 必须存在的护栏（否则视为未实现）

1. **步数上限**：单轮任务工具调用次数有硬上限，超出即停并告知用户（防止无限循环烧钱）。
2. **超时上限**：单轮任务总时长有硬上限，超时即停并保留已有产出。
3. **随时可中断**：用户点「停止」后，后端必须立即停止后续工具调用，不只是停止渲染。
4. **决策可追溯**：每次工具调用都要留下「工具名 + 参数 + 结果摘要」的记录，可被 UI 展示。
5. **敏感数据出网需明示**：本地文件被读取后其内容会随 prompt 进入模型 —— 若选云端模型（DeepSeek），等同于**内容离开本机**。这一点**必须在 UI 上让用户知情**，具体策略见待拍板项 P3。

### 3.3 明确不做「安全机制」

HITL 审批工作流引擎、权限分级策略系统、细粒度审计日志平台、沙箱隔离容器。本期用**白名单 + 上限 + 可中断**这三件朴素的事，不做安全平台。

## 4. 本期不做（Out of Scope）

| # | 排除项 | 说明 |
|---|---|---|
| 1 | 多智能体协作 | 只有一个 agent，不做角色分工 / 互相评审 / 辩论 |
| 2 | 长期记忆库 / 向量检索 | 记忆 = 单个会话内的对话历史，不跨会话、不建索引 |
| 3 | 可视化工作流编排 | 无节点画布、无拖拽流程、无「工作流」概念 |
| 4 | 云同步 / 账号体系 | 纯本地单机 |
| 5 | 工具市场 / 自定义工具热插拔 | 工具集在代码里写死三个，用户不能加 |
| 6 | 写入类工具 | 见 §2「明确不做的工具」 |
| 7 | 定时任务 / 后台常驻 / 主动唤醒 | agent 只在用户提问后被触发 |
| 8 | 多任务并行 | 同一时刻只跑一个 run |
| 9 | MCP / 外部工具协议接入 | 本期不引入协议层 |
| 10 | 复杂审批与权限策略 | 见 §3.3 |
| 11 | 多模态输入（图片 / 语音 / 附件上传） | 仅纯文本 |
| 12 | Agent 自主「规划树」可视化、token / 费用统计面板 | 过程可见只到「步骤列表」粒度 |

## 5. 验收标准（什么算「harness 做完了」）

全部判据为**静态核对**或**用户手动运行**，不含任何自动化校验。

### 5.1 功能验收

| # | 验收项 | 判定方式 |
|---|---|---|
| A1 | 用户发一句需要外部信息的问题，agent 自己发起搜索并基于搜索结果给出回答（而非模型凭空作答） | 手动：提问后看到搜索步骤，最终答案含搜索结果中的信息 |
| A2 | 用户给出本地文本文件路径，agent 自己读取并基于文件内容回答 | 手动：提问后看到读文件步骤，答案与文件实际内容一致 |
| A3 | 至少跑通一次**多步任务**：≥2 次工具调用串联完成一件事（如先搜索、再打开某条结果、再计算） | 手动：步骤列表中出现 ≥2 个不同工具调用 |
| A4 | 计算类问题由 `calculator` 完成 | 手动：步骤列表出现计算调用，结果数值正确 |
| A5 | 步骤可见：UI 能展示每一步的工具名 + 参数 + 结果摘要 | 静态：存在步骤记录的数据结构与渲染分支；手动：界面可见 |
| A6 | 可中断：生成中点「停止」后，后端不再发起新的工具调用 | 静态：中断信号链路贯通到后端循环；手动：停止后步骤不再增加 |
| A7 | 步数上限生效：构造一个会绕圈的任务，达到上限后自动停止并给出说明 | 静态：循环存在上限判断；手动：观察到自动停止且有提示 |
| A8 | 失败可解释：工具报错（搜索失败 / 文件不存在 / 无权限）时，用户能看到失败原因，agent 会尝试替代方案或明确放弃 | 手动：故意给一个不存在的路径，界面给出可读原因 |
| A9 | 红线可验证：请求 agent 删除文件 / 执行命令 / 对外发消息时，被明确拒绝并说明原因，不是静默无响应 | 静态：工具白名单存在且不含危险工具；手动：提出此类请求得到拒绝说明 |
| A10 | 错误态可读：未配置模型 / Key 无效 / Ollama 未启动时，UI 给出与现有一致的中文提示 | 手动：清空配置后发问，出现明确引导 |
| A11 | 回归不破：原有直连对话（会话历史、流式、模型切换、配置保存）在改造后仍可用 | 手动：不改任何配置直接聊天，表现与改造前一致 |

### 5.2 完成定义（Definition of Done）

**harness 本期视为完成，当且仅当**：A1–A11 全部通过，且用户在他的 Windows 机器上手动跑通「搜索后总结」与「读文件后回答」这两个场景，并认可过程可见性足够。

> 任何一条不满足即不算完成；不接受「功能可用但过程不可见」或「跑通但红线无约束」的交付。

## 6. 与现有系统的接缝（仅供架构师参考，非范围要求）

1. **Electron 侧变化最小化**：现有 `chat:send` / `chat:chunk` / `chat:end` / `chat:error` 事件模型可继续沿用，`chat:send` 的语义从「调一次模型」变为「提交一个 agent run」。
2. **需要新增事件类型**：用于把「工具步骤」推给渲染层（工具开始 / 工具结束 / 结果摘要）。
3. **现有直连 Provider 的去留**是待拍板项（见 P9），本期不做决定。
4. **Python 进程的生命周期管理**（谁拉起、端口与鉴权方式、崩溃后行为）是待拍板项（见 P1），本期不做决定。

## 7. 待用户拍板的点

> 以下每项**均未预设倾向**，仅列出可选路径与影响面，等用户决定后回填本文档。

| # | 需要拍板的点 | 可选路径 | 影响面 |
|---|---|---|---|
| **P1** | Python 后端怎么跑起来 | ① Electron 自动拉起子进程 ② 用户手动启动（开发期最简单）③ 打包时分发独立可执行文件 | 打包体积、分发难度、启动体验、调试便利性 |
| **P2** | 搜索能力从哪来 | ① 第三方搜索 API（需用户自备 Key）② 免 Key 抓取（可能被限流 / 结果不稳定）③ 本期不做搜索，工具只剩「读文件 + 计算」 | **直接决定 MVP 工具集是 3 个还是 2 个**；US-1 是否成立；是否增加一个配置项 |
| **P3** | 本地文件内容出网的边界 | ① 仅当使用本地 Ollama 时才允许读文件 ② 每次读文件前弹确认 ③ 不限制但 UI 常驻提示 | §3.2 第 5 条的实现方式；US-2 的使用门槛；UI 复杂度的唯一显著增量 |
| **P4** | 允许读哪些路径 | ① 每次由用户通过文件对话框手动选定 ② 允许一个配置的「工作目录」及其子目录 ③ 任意路径 | 安全红线强度、`read_text_file` 的易用性、白名单实现复杂度 |
| **P5** | 步数上限与超时的具体数值 | 如最多 N 步 / 单轮 M 秒。需用户给一个能接受的心理上限 | 成本可控性、复杂任务成功率、UI 是否需要「继续」按钮 |
| **P6** | 工具步骤是否展示给用户 | ① 全部展开 ② 折叠成一行摘要（点开看详情）③ 完全隐藏只看最终答案 | US-4 是否成立；UI 改动量；与「简约、不要花里胡哨」红线的平衡 |
| **P7** | 是否引入「调用前人工确认」 | ① 全部自动执行 ② 仅首次使用某工具时确认 ③ 每次调用都确认 | 交互打断感、安全强度、多步任务的可用性 |
| **P8** | 是否坚持「本期零写入」 | ① 是，严格只读 ② 否，允许写入限定工作目录 | 安全红线范围、US-2 的实用性、可逆性风险 |
| **P9** | 现有直连模式去留 | ① 保留作为 harness 不可用时的降级路径 ② 移除，统一走 harness | 双路径维护成本、故障时的可用性、代码复杂度 |
| **P10** | LangChain 的使用深度 | ① 用现成的 Agent 循环框架 ② 只用它的工具抽象、循环自己写 ③ 完全不引 LangChain | 依赖体积、调试可控性、与用户「点名 LangChain」的意图一致性 |
